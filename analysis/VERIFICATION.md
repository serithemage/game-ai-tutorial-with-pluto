# 통합 튜토리얼 검증

## 실제 분석 근거

원본 배포물·Ghidra·JDK의 다운로드 해시, 가중치 컨테이너의 선언된 텐서 크기·범위 검사는 기존 분석에서 수행했다. 해당 바이트·REA 근거를 통합 튜토리얼에서 재사용한다. 실제 대전이나 훈련 실행을 검증한 것은 아니다.

## 통합 HTML의 검증

- 가중치 조합의 방향, 음수·0 경계, 소수 오차, 기억의 양끝, 양자화와 잘못된 비율을 Node 테스트로 확인한다.
- 배포하는 `_site/`의 상대 링크와 앵커, HTML ID, JSON, CC 라이선스, 외부 자료 안내를 확인한다.
- 원본 바이너리, 로컬 사용자 설정 진단과 제공자 캐시가 배포에 들어가지 않는지 검사한다.
- 브라우저에서 정찰 전환, 키보드 슬라이더, 초기화, 기억 비율, 양자화, 학습 단계, 이해 확인, 근거 펼치기를 검사한다.
- PC 1440px, 모바일 390px·320px의 가로 넘침과 화면 배치를 검사한다.
- JavaScript 없이 본문과 학습 설명을 읽을 수 있는지 검사한다.

```sh
npm run check
BASE_URL=http://127.0.0.1:8765/_site/ npm run test:browser
```

[배포 파일 검사](evidence/artifact-verification.json)와 [브라우저 검사](evidence/browser-verification.json)에 실제 결과를 기록했다. 링크 검사 항목 수는 파일 수와 인용 링크에 따라 달라진다. 브라우저 화면은 `tools/site-review/`에 로컬로 보관한다.

## 확인하지 않은 범위

StarCraft의 실제 경기, 모델 훈련, 승리 예측의 보정, 실전 속도·실력, 전체 입력 필드와 행동 매핑은 이 튜토리얼 검증 범위 밖이다. 분석 보고서에서 확인한 범위에 맞춰 설명한다.

## 공개 배포 확인

[배포 기록](evidence/pages-publication.json)에 첫 성공 배포의 커밋과 workflow를 보존했다. 공개 GitHub Pages 주소에서 HTML·CSS·JavaScript·분석 보고서·라이선스의 HTTP 200을 확인했다. 공개 사이트에서 PC·모바일 조작 및 JavaScript 없는 읽기를 다시 검증했다. 최초 배포는 Pages 설정 활성화 전에 시작되어 실패했으며, 설정 확인 뒤 같은 workflow를 재실행하여 성공했다.
